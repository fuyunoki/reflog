# REFLOG 世界観

このゲームの文章を書くときの一次資料。ステージ JSON の intro / outro / narrative、
語彙カード（`content/lexicon/*.json`）は、すべてここに従う。

矛盾が出たらこのファイルが正しい。ここを直さずに本文だけ直してはいけない。

---

## 1. 芯 —— 観測局とは何か

**観測局は、本番の履歴を預かっているチームの比喩である。**

時間旅行という語彙は残したまま、中の役割・規則・制限を実務に一対一で対応させる。
プレイヤーはエンジニアであると想定してよい。だから「想像できない架空の役職」を作らず、
**読めば自分の職場の誰かに当てはまる**ように書く。

| 世界観の語 | 実務での正体 |
| --- | --- |
| 観測局 | 本番の履歴を預かっているチーム |
| 修正官（プレイヤー） | 本番の履歴に直接手を入れられる権限を持つ人 |
| 世界線 | ブランチ |
| 時点 | コミット |
| 回収 | 別チーム・別ブランチから変更を持ち込むこと |
| 観測記録 | 変更の説明。何を・なぜ変えたか |
| 因果負荷の上限 | 影響範囲の予算、レビュー規約 |
| 手数の上限 | 一度の作業で触ってよい範囲 |
| 演習（訓練） | 検証環境。壊しても誰も困らない |

### 修正の三原則

局の規則であり、そのままゲームのルールであり、そのまま実務の運用ルールである。
**この三つが一致していることが、この作品の設計そのもの。**

| 原則 | 実務での意味 | ゲームでの現れ方 |
| --- | --- | --- |
| 一. 消すな、打ち消せ | 共有ブランチでは `reset` せず `revert` する | 因果負荷 5 対 2 |
| 二. 起きたことは記録に残せ | 履歴を改変しない | `historyPreserved` の任意条件 |
| 三. 判断した者の名前を残せ | 衝突をどう解決したか、意図を記録に残す | 決着が記録として積み上がる |

### なぜ直すのか

捻じれた世界線は、放っておくと周りの記録を巻き込んで崩れる。
局は「あるべき形」の判断基準を持っている —— ということになっている。

**誰がその基準を決めているのかは、局内でも説明されない。**
ここは第三章の問い「誰が修正官に命令しているのか」への伏線なので、
それまで答えを書かない。ほのめかしだけを置く。

## 2. 命名規則

### 局の人間は片仮名の呼び名

局の記録に残るのは呼び名だけで、本名は残っていない。いつからそうなのかは誰も知らない。

**本名が失われている**という設定は、`reflog`（消したはずのものの記録）という
作品の主題と直接響く。最終章で回収する余地として空けてある。

### 局の外の人間は実名

事案の当事者は漢字の実名で書く（例：霧島 湊）。
局の人間と、局が直そうとしている人間が、表記の上で区別される。

### 地名は実在しない和風の二字

白鷺、灰崎、苫江 —— 色か自然物を含む二字。以後もこの系統で揃える。

### 性別を固定しない

修正官（プレイヤー）は無名・無性別。フユノキ、シンドバッド、ジュダルも同様に、
性別を特定する語を使わずに書く。日本語の地の文なら自然に書ける。

## 3. 人物

### フユノキ

語り手。**レビュアーにあたる。** 修正に立ち会い、手を入れる前に方針を確認し、
終わったら講評する。職名は本文に出さない。常に「フユノキ」と呼ぶ。

**性格**

- 見た目は若い。誰に対しても丁寧で、新人の修正官にも、事案の死者にも、同じ態度で接する
- 明るく人懐こい。重い事実を、何でもないことのように軽い口調で告げる
- 局の誰よりも古い記録を知っている。いつからここにいるのかが分からない
- 答えを持っているのに言わない。**決めるのは常に修正官だ**と譲らない

最後の一点が重要で、これがゲームの中核（矛盾の決着、`revert` と `reset` の選択）と
直接結びついている。フユノキは正解を教えない。判断の材料だけを渡す。

**文体**

導入（intro）と講評（outro）はフユノキが語っている場面なので、丁寧な言い方にする。

> 最初の術式を渡しますね。REVERT —— 起きた出来事を打ち消す力です。

盤面の手引き（guide）と助言（hints）は「手順の表示」なので、短い断定形のまま残す。
ここを丁寧にすると、操作の指示が読み取りにくくなる。

### シンドバッド

別チームの回収担当。別の世界線へ入り、記録を持ち帰ってくる。

回収を**取り仕切る側**であり、現場にも出る。食えない人物として書く。
持ち帰ったものが本当に「回収」だったのか —— つまり、
あちらから奪ってきたのではないか、という疑いを後の章に残す。

`merge` と `cherry-pick` の場面で顔を出す。

### ジュダル

退職した前任の修正官。規則を意に介さず、履歴を消して回った。

`ch0-06` の「前任者が二度 RESET を使った記録」はこの人のもの。
修正の三原則を真っ向から破る存在として置き、
なぜいなくなったのかを後の章の問いにする。

### 霧島 湊（きりしま みなと）

局の外の人。白鷺研究所の研究員。1998年11月4日、火災で死亡。
位相計の系譜にある観測装置を単独で組んでいた。

## 4. 年表 —— 位相計の系譜

本編三本は独立した事案ではなく、一本の線で繋がっている。
章は時代を**遡る**順に並んでおり、進むほど原因に近づく。

| 年月 | 場所 | 出来事 | ステージ |
| --- | --- | --- | --- |
| 1969年8月 | 苫江 | 別の世界線で位相計が完成していた。同じ世界線では三日後に市街が焼失。局は**完成だけを持ち帰った** | `ch1-03` |
| 1981年3月 | 灰崎観測所 | 位相計を積んだ観測所。記録がひとつ書き換えられ、退避計画が撤回され、地区が被災。**誰が書き換えたかは残っていない** | `ch1-02` |
| 1998年11月 | 白鷺研究所 | 霧島湊が位相計の系譜にある装置を単独で組んでいた。火災で霧島は死亡し、装置は封印。**この火災は本来起きないはずだった** | `ch1-01` |

### 縦軸

1969年に、一つの出来事だけを抜き出して持ち帰った。
その代償が、1981年と1998年に出ている —— という読み筋。

**「なぜ世界線は壊れるのか」の答えが「我々が直したからだ」に近づいていく。**

`ch1-03` の既存 outro「何も持ち込まなければ、あの発明もなかった。そういう取引だった」が、
そのまま伏線として効く。

## 5. 訓練

観測局が演習用に作った、**実在しない世界線**。だから何度でもやり直せる。
実務でいえば検証環境にあたる。

訓練の舞台（観測室、水路、記録保管庫、標識灯など）は演習課題であって、
実在の場所ではない。だから語彙カードには登録しない。

本編に入った瞬間に「ここからは実際の記録だ」という重みが立つ。
`ch1-01` の intro にすでにその一行がある。

## 6. 語彙カード

`content/lexicon/*.json`。本文中に登録語が出てきたら下線が引かれ、押すと開く。
初出のものはステージ導入を閉じた直後に一度だけ自動で出る。

### 載せるもの

- 本編の人物・場所（霧島湊、白鷺研究所、灰崎観測所、苫江、位相計）
- 局の人物（フユノキ、シンドバッド、ジュダル）
- 局の用語（観測局、修正官、世界線、時点、因果負荷、回収、演習）

### 載せないもの

- 訓練の舞台（演習課題なので実在しない）
- git コマンドの対応表（ホームの「言葉の対応」が担当している）

### 実務での対応

**役割・用語のカードには `practice` を必ず書く。** 事案側のカード（霧島湊、白鷺研究所など）には書かない。
解説が物語の場面に挟まると、事件の重みが落ちるため。

## 7. 背景

場所ごとに、ごく薄い地紋を敷く。情景を描くものではなく、
「別の場所に来た」ことが分かる程度の手掛かり。

| 場所の種別 | 模様 |
| --- | --- |
| 施設・建物 | 格子 |
| 屋外・地区 | 等高線 |
| 水路・海 | 波形 |
| 地下・書庫 | 断面 |

形は場所の id をシードにして振る。観測任務（自動生成）は任務番号がシードになるので、
何もしなくても任務ごとに違う地紋が出る。
